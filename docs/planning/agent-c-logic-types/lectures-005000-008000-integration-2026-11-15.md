## Scope and proof-model cautions

- Do not equate **definitional equality** with theorem-driven rewriting. In a chosen recursion orientation, one of `m + 0 = m` and `0 + n = n` may calculate while the other requires induction.
- Distinguish Lean's proof-irrelevant `Prop` from richer identity semantics of HoTT; do not claim all intensional type theories identify equality proofs.
- Dependent pattern matching is explained as elaboration to recursors and equality handling, **not** as a new kernel axiom.
- Kernel acceptance is *relative to accepted axioms and trusted mechanisms*; a `sorry` is not a completed proof, and `native_decide`-style evaluation introduces a different trust consideration.
- Formal proof of a stated proposition is distinct from the **adequacy of that specification** and any connection to a concrete implementation.

The Lean snippets in companions illustrate interfaces. This delivery did not compile them; the claims are grounded in the official Lean textbook and reference manual. The ZIP contains no shared reader or test changes.

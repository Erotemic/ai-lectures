# When a Stack Changes the Language

Imagine a pair of parentheses. Between the opening and closing marks, you can place another pair. And inside that pair, another. You can also put two balanced groups side by side. A reader has to recognize both nesting and sequence. How much memory does that require?

A finite automaton can remember a fixed amount about a prefix. It can check whether the last symbol was an opening parenthesis, or whether the number of openings is even. But it cannot, in general, remember arbitrarily many unmatched opening parentheses. Nor can a finite automaton recognize all words made from n occurrences of the symbol a followed by exactly n occurrences of b, with no bound on n. There are infinitely many distinguishable prefix counts.

One way past this limit is not to give the machine every power of a general computer. Give it just one new data structure: a stack. The stack stores a sequence of symbols. We can push a symbol onto its top, inspect the top, and pop it. We cannot jump directly to a deep element or edit the middle. Nonetheless, one unbounded stack dramatically expands the kinds of patterns a machine can recognize.

Before we build the machine, let us describe the language in another way, through a grammar. A context-free grammar specifies a finite set of variables, a finite terminal alphabet, a designated start variable, and finitely many production rules. Each rule replaces one occurrence of a single variable with some finite sequence of variables and terminals. Starting from the start variable, repeatedly apply rules until only terminal symbols remain. The resulting words constitute the language generated by the grammar.

The phrase 'context-free' refers to the left side of each replacement: the rule applies to a variable regardless of the symbols around it. It does not mean that the language is insensitive to nesting or relationships between parts. In fact, context-free grammars can describe relationships that regular languages cannot.

Take the grammar with one variable, S, and two rules. The first says S may be replaced by an a, followed by S, followed by a b. The second says S may be replaced by the empty word. If we choose the second rule immediately, we generate the empty word. If we choose the first rule once and then the second, we generate a-b. If we choose the first rule twice and then the second, we generate a-a-b-b.

Why exactly this language? Every use of the recursive rule adds one a at the left and one b at the right. A derivation that eventually ends after n recursive uses therefore yields n a's followed by n b's. Conversely, for every nonnegative n, applying the recursive rule n times and then the empty rule generates that word. We have proved both inclusions, so the generated language is exactly the equal-count block language.

Now construct a stack machine for it. The machine starts in a phase in which a's are allowed. For every a it reads, it pushes one marker onto the stack. On the first b, it switches to a phase in which only b's are allowed. Each b must pop one marker. It rejects if a b arrives when there is no marker to pop, if an a appears after the b phase has begun, or if input ends while markers remain. It accepts at the end of the input when the stack has returned to its bottom marker. The empty input is accepted too.

The invariant is simple and strong. While we are reading the initial a block, the stack contains one marker per a read. Once we enter the b phase, it contains the number of a's not yet matched by b's. Because no a can follow a b, every accepted word has the required block order. The empty-stack condition makes the two counts equal. Conversely, every word with equal blocks leads through legal transitions and empties the stack. This is a deterministic pushdown recognizer for this particular language.

The words 'for this particular language' are important. A pushdown automaton may be nondeterministic, and in the general theory nondeterministic pushdown automata recognize exactly the context-free languages. Deterministic pushdown automata are weaker; not every context-free language has one. We should not reason from this easy deterministic example that every grammar can be parsed by the same kind of deterministic stack procedure.

Return to parentheses. Here is a remarkably compact grammar for balanced strings using one type of parenthesis. It says a balanced string is either empty, or an opening parenthesis, followed by a balanced string, followed by a closing parenthesis, followed by another balanced string. The first recursive part represents what is nested inside a pair; the second represents what follows that pair.

Consider the string opening, opening, closing, closing, opening, closing. We might write it visually as two opening marks, two closing marks, then an opening and a closing mark. The outer first pair encloses an inner pair; the final pair is a separate group. Both nesting and side-by-side composition are accounted for by the grammar.

A stack recognizes the same language: push for each opening mark, pop for each closing mark, reject if a closing mark arrives with no unmatched opening mark, and accept if the stack is empty at the end. For a single kind of parenthesis, the stack depth could even be represented by an unbounded counter. For several matching bracket types, we need to remember which kind of opening bracket is on top. A stack does that directly.

These two descriptions, generative grammar and recognizing stack machine, reflect different ways of thinking about the same family of languages. One describes how a structure can be built. The other describes how a word can be checked. There is a theorem that every context-free grammar can be converted into an equivalent nondeterministic pushdown automaton, and conversely. The conversions are not trivial, but the forward direction offers a useful idea.

Place the grammar's start variable on the stack. If the top is a variable, nondeterministically choose one of its production rules and replace the variable by the rule's right-hand side, pushed in an order that exposes the next symbol first. If the top is a terminal, match it against the next input symbol and pop it. Accept when all input is consumed and the stack is empty. A successful computation is exactly a grammatical derivation; the machine explores derivations without committing to a single one in advance.

We must be honest about the limits of that sketch. Left-recursive rules or unproductive choices can cause an incautious simulation to loop along one path. Nondeterministic acceptance is existential over paths, and a real recognizer needs a fair search or a parsing algorithm that guarantees termination on the input. The equivalence theorem does not endorse naïvely following one guessed derivation forever.

One of the most important facts is that context-free language membership is decidable. Given a context-free grammar and a finite input, there is an algorithm that always terminates and determines whether the grammar generates that input. This is stronger than saying that we can enumerate successful derivations until we find one. The latter might never stop when the answer is no.

A standard way to obtain a terminating recognizer is dynamic programming over substrings. First transform the grammar into an appropriate normal form, in which ordinary rules either replace one variable with two variables or replace a variable with one terminal symbol, with a separate convention for the empty word. For every interval of the input, record which grammar variables can derive exactly that substring.

For substrings of length one, the answer comes from terminal rules. For a longer substring, try every possible split point. A variable A can derive the interval if it has some rule A becomes B followed by C, where B derives the left interval and C derives the right. Build the table in increasing order of substring length. Since each subinterval is shorter, the required entries have already been calculated.

This algorithm is often called C-Y-K, after Cocke, Younger, and Kasami. For a fixed grammar in the stated normal form, a straightforward implementation takes cubic time in the input length and quadratic space for the chart, up to factors depending on grammar size. The important point is not that every grammar must be parsed this way, or that cubic time is optimal for every practical grammar. It is that a finite dynamic program gives a guaranteed answer for every input.

Here is an exact worked grammar for the positive-count language: one or more a's followed by an equal number of b's. Let A generate the terminal a, and B generate the terminal b. Let S either produce A followed by B, or A followed by T; let T produce S followed by B. The shortest derivation makes a-b. The longer rule surrounds a smaller S with one new a and one new b. Every production is already in the two-variable or one-terminal format required by the dynamic program. The empty word can be treated as a separate accepted case if we want the nonnegative-count language.

The chart for a-a-b-b eventually records that S derives the whole four-symbol interval. For a-a-b, it does not. The result is justified by induction on substring length: terminal rules settle length one, and every longer normal-form parse has a root rule with a left and right subtree. The algorithm considers exactly those splits, neither missing a valid parse nor inventing one.

A grammar also carries structural information, and structural information introduces another issue: ambiguity. Imagine an arithmetic grammar in which an expression can be an expression plus an expression, an expression times an expression, or a single identifier. The text 'x plus x times x' has two distinct parse trees. One treats addition as the outer operation; the other treats multiplication as the outer operation. The grammar does not determine operator precedence. Even if two parses happen to yield the same numeric result for some chosen values, they remain different structural explanations.

Ambiguity is a property of a grammar: some string has more than one parse tree. A language may be described by both ambiguous and unambiguous grammars, and some context-free languages are inherently ambiguous. This means that finding a convenient grammar and deciding whether a program's syntax has the structure we intend are not interchangeable tasks. Parser construction needs explicit commitments about precedence, associativity, and allowable forms.

Does one stack solve every pattern-counting problem? No. Consider three consecutive blocks: n a's, followed by n b's, followed by n c's. This language is not context-free. It is possible for a general computer to check it with two counters, but a single context-free grammar or ordinary nondeterministic pushdown automaton cannot recognize exactly those words.

There is a pumping lemma for context-free languages, which is different from the regular-language pumping lemma. For a sufficiently long generated word, a suitably chosen pair of pieces within a bounded window can be repeated together or removed together while preserving membership. Choose a word made of p a's, p b's, and p c's. The bounded window cannot touch both an a and a c, because an entire block of p b's separates them. At least one of the three symbol types therefore cannot occur in either pumped piece. But the pumped pieces are not both empty. Removing them changes the count of at least one other type while leaving one count fixed, so the three counts cannot remain equal. That contradicts the pumping property, proving the language is not context-free.

The result also shows that context-free languages are not generally closed under intersection. The language with equal a and b blocks followed by any number of c's is context-free. So is the language with any number of a's followed by equal b and c blocks. Their intersection requires all three counts to be equal, which is not context-free. Compare this with finite automata, where the product construction made intersection automatic.

We have climbed one step in expressive power. Finite-state machines handle exactly the regular languages. A stack permits context-free structures such as unbounded nesting and matched blocks. General Turing machines go further. The difference is not merely computational speed. It changes which languages can be recognized at all.

Noam Chomsky's work in the nineteen fifties connected families of grammars with different generative powers. Yehoshua Bar-Hillel, Micha Perles, and Eli Shamir developed foundational properties of these grammars, including work behind the context-free pumping lemma. Jay Earley's nineteen seventy parsing work is another important historical example of how general grammar recognition became an algorithmic problem. These are distinct contributions; the theory of grammars did not spring from one complete textbook formulation.

When engineering a parser, think in layers. A regular-language recognizer may be ideal for a token class or simple streaming protocol. A context-free grammar may describe nested syntax and give rise to parse trees. Later checks may need symbol tables, types, or constraints that the grammar alone does not express. The right mathematical model is neither the strongest model available nor the model with the most fashionable name. It is the weakest model that faithfully captures the information the task requires, with proofs and algorithms that exploit that restriction.

## Exact formal companion

### Context-free grammars

A CFG `G=(V,Σ,R,S)` has finite nonterminal set `V`, finite terminal alphabet `Σ` disjoint from `V`, production rules `A→α` with `A∈V`, `α∈(V∪Σ)*`, and start variable `S∈V`. A derivation replaces a variable at any position according to a rule. Define `L(G)={w∈Σ*: S⇒* w}`.

For `G_equal` with `S→aSb | ε`, induction on the number of recursive expansions proves `L(G_equal)={aⁿbⁿ:n≥0}`. An explicit derivation is `S⇒aSb⇒aaSbb⇒aabb`.

For one-bracket Dyck strings, `S→ε | (S)S` generates balanced words, including concatenation: the first `S` represents an internally balanced factor, the second represents the balanced suffix after the first matching close. Parenthesis depth is bounded below by zero for every prefix, with final depth zero; a one-stack recognizer checks precisely this property.

### Stack recognizer for equal blocks

States `A_PHASE`, `B_PHASE`, `REJECT`; stack alphabet `{Z,X}` with bottom marker `Z`. Start in `A_PHASE` with stack `Z`. In `A_PHASE`, on `a` push `X`, on `b` require `X` on top then pop and switch to `B_PHASE`. In `B_PHASE`, on `b` require and pop `X`; on `a` reject. At end accept only if stack is `Z`, including empty input in `A_PHASE`. When there are more `b` than prior `a`, a pop of `Z` rejects. Correctness is by invariant: the number of `X` markers equals `#a-#b` consumed, and phase enforces `a* b*`.

**Nondeterministic PDA equivalence:** A PDA with nondeterministic choices recognizes exactly the context-free languages. The grammar-to-PDA construction maintains the remaining sentential form on a stack, expanding variables by ε moves and matching terminal symbols against input. The reverse construction is less immediate; the lecture asserts the established theorem without pretending its sketch constitutes both directions. Not every CFL is accepted by a deterministic PDA.

### A fixed-grammar CYK chart

For nonempty `aⁿbⁿ`, use `V={S,T,A,B}` and rules

```
S → A B | A T
T → S B
A → a
B → b
```

All productions are of the Chomsky-normal-form types `X→YZ` or `X→a`. `S⇒AT⇒ASB⇒AABB⇒aabb`. The grammar recognizes `n≥1`; deal with `ε` explicitly for the `n≥0` language.

For a normal-form grammar and `w=w₀...wₙ₋₁`, define a chart `C[i,j]` of variables deriving `w[i:j]` for `0≤i<j≤n`. Base case `C[i,i+1]={A:A→w_i}`. For `j-i≥2`, put `A` into `C[i,j]` iff there exist `i<k<j` and `A→BC` with `B∈C[i,k]`, `C∈C[k,j]`. A word belongs iff `S∈C[0,n]`, with the separate legal-empty-word check if needed.

Correctness follows by induction on interval length and root decomposition of every normal-form parse tree. For fixed grammar, run time `O(n³)` and chart storage `O(n²)` sets of grammar variables. With grammar size visible, rule-scanning contributes a grammar-dependent factor; normal-form conversion also has a cost. Neither is hidden in an end-to-end complexity claim.

### Why `aⁿbⁿcⁿ` is not context-free

Context-free pumping lemma: if `L` is context-free, there exists `p≥1` such that each `w∈L` with `|w|≥p` decomposes as `w=uvxyz`, `|vxy|≤p`, `|vy|≥1`, and `uv^t x y^t z∈L` for every `t≥0`. Suppose `L={aⁿbⁿcⁿ:n≥0}` and choose `w=aᵖbᵖcᵖ`. Because `|vxy|≤p`, it cannot contain both an `a` and a `c`, so at least one block symbol does not occur in `v` or `y`. Since `|vy|≥1`, removal at `t=0` changes at least one count and leaves at least one other count unchanged. Equality of all three counts is destroyed, contradiction. This proof uses the stated form and correct quantifier order; it is not an assertion about a specific parser's resource bounds.

For closure, let `L1={aⁱbⁱcʲ:i,j≥0}` and `L2={aⁱbʲcʲ:i,j≥0}`. Both are context-free (concatenate a balanced two-block grammar with a regular block). Their intersection is `aⁿbⁿcⁿ` and is not context-free. Closure under union plus hypothetical closure under complement would imply closure under intersection by De Morgan, so CFLs are not closed under complement either. Context-free languages *are* closed under intersection with regular languages by product of a PDA and a DFA.

### Ambiguity is structural

For grammar `E→E+E | E*E | id`, `id+id*id` has distinct trees with root `+` and root `*`; a conventional parser must encode precedence to disambiguate. Existence of one ambiguous grammar does not imply the language is inherently ambiguous. The worked finite counter in the companion script uses the separate grammar `E→E+E | x` and counts two trees for `x+x+x`, five for `x+x+x+x`.
